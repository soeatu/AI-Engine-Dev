# システム開発領域

このフォルダでは、要求整理、設計、実装、テスト、障害調査を行います。

## フォルダの役割

- `projects/`: 個別システムまたは機能ごとの成果物とソースコードを置く。
- `skills/`: 開発で繰り返し使うAI向け手順を置く。工程に合うSkillの選択は`skills/README.md`を参照する。
- `scripts/`: ビルド、テスト、解析などを自動化する処理を置く。
- `templates/`: 要求、設計、テスト、調査報告などのひな型を置く。
- `tests/`: ワークスペース共通の検証やサンプルテストを置く。

## 作業手順

1. 利用者、目的、対象範囲、制約、受け入れ条件を確認する。
2. 現行仕様、ソースコード、環境、ログを調査し、推測と事実を分ける。
3. 影響範囲と設計を整理し、レビュー可能な小さな単位で実装する。
4. 単体、結合、E2Eなど必要なレベルで検証し、結果を記録する。
5. 変更内容、確認済み事項、未確認事項、残るリスクを引き継ぐ。

完了条件は、受け入れ条件を満たす証拠があり、変更の影響と未確認事項を次の担当者が判断できることです。

## Skillの使い分け

要求、仕様、設計、計画、実装、検証、レビュー、デリバリーのうち、依頼に必要な工程だけ`skills/README.md`から選びます。Skillの利用は、コミット、push、Issue作成、デプロイなどを自動的に許可するものではありません。外部状態を変える作業は、依頼内容とプロジェクト固有の規則に従います。

承認済みの設計・実装計画を役割別モデルへ委譲し、Task単位の実装、レビュー、修正、全体レビューまで連続実行する場合は、`skills/orchestrated-development/SKILL.md`を使用します。
