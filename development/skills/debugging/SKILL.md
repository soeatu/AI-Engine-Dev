# Debugging

エラーを見て即座にコードを変えず、まずBugで赤になる短いFeedback loopを作る。ログや入力に機密情報がある場合は、保存や共有の前にRedactする。

## 進め方

1. 発生環境、Version、入力、時刻、期待値、実際の結果を固定し、最小のコマンドまたは操作で再現する。
2. Loopを短くし、単独実行、関連Test、最小データ、直前の変更、境界ごとの観測から故障範囲を狭める。
3. Reproductionから不要な要素を一つずつ除き、Bugを残す最小ケースを作る。
4. 根拠に基づく原因仮説を複数挙げ、可能性と確認コストで順位付けする。各仮説を「Xが原因ならYを変えるとZになる」という反証可能な予測にする。
5. Debugger、対象を絞った計測、識別可能な一時ログの順で、一度に一変数だけ変えて仮説を検証する。性能問題はBaselineを測定してから比較する。
6. 根本原因を、症状、発生条件、因果経路、裏付ける証拠として説明する。
7. 修正が依頼されている場合は、正しいSeamで回帰TestをREDにし、最小修正後にGREENと元の再現手順を確認する。
8. 一時ログ、Probe、試作を除去し、関連する全検証を再実行する。

## 完了条件

- 元の症状を安定して再現または観測できる。
- 根本原因の仮説が証拠で支持され、代替仮説との違いを説明できる。
- 修正した場合は回帰Testと元のScenarioの双方で解消を確認している。
- 再現できない場合は、試した条件、得られた証拠、次に必要な観測を明記している。
