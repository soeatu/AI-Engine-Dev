Deck: AI-Engine-Dev workspace guide
Mode: revision
Audience: Workplace colleagues who will use AI-Engine-Dev; assume they understand ordinary file and folder operations but may not know Agent Skills or this repository's workflow.
Purpose: Explain what AI-Engine-Dev can do, how to prepare a usable environment, how to give the first request, and what artifacts and verification evidence remain after use. Folder roles and Skill catalogs support those answers instead of leading the narrative.
Use context: Detailed instructional reference for asynchronous reading, onboarding, and team explanation. It is not primarily a presenter-led pitch deck.
Expected decision or action: Readers can decide whether the workspace fits their task, prepare either an AI-Engine-Dev or copied-project environment, issue a concrete first request, and locate the resulting files, checks, and remaining human decisions.
Central takeaway: AI-Engine-Dev is not a separate application; it is a reusable set of AI work instructions, templates, generation tools, and verification rules that turns a request into reviewable artifacts inside Codex or Claude Code.
Communication job: By the end, workplace colleagues should be able to prepare the environment and complete a first Development or Presentation task because capabilities, setup commands, request examples, and resulting artifacts are shown in that order.
Scope: Focus on development/ and presentation/. Lead with capabilities, environment preparation, first-use examples, and before/after outcomes. Explain folder roles and Skill families only after the reader understands the use case. Keep the full Skill catalog as a reference appendix rather than the main explanation. Mention Lerning/ only as an optional onboarding entrypoint. Do not reproduce every line of every SKILL.md; link readers to canonical files for exact procedures.
Constraints: Japanese; 16:9; detailed enough for standalone reading; editable native PowerPoint objects; readable without narration; accessible contrast; no confidential information; no unsupported claims; slide count may grow as needed. Template phase precedes final deck authoring.
Template direction: Neutral professional technical-manual style, using the repository's current neutral design tokens. This is not an official employer brand. No logo until an approved asset is supplied.
Proposed reusable layouts:
1. Cover: title, document role, audience, version/context.
2. Section divider: section purpose and what the reader will learn.
3. Folder map: hierarchy with roles and canonical entrypoints.
4. Concept flow: input -> Skill selection -> work -> validation -> handoff.
5. Skill catalog: category, when to use, primary output, and cautions.
6. Routing guide: task/question-based decision path to the correct Skill.
7. Step-by-step procedure: numbered actions with inputs, outputs, and checks.
8. Comparison: development and presentation responsibilities and boundaries.
9. Evidence and caution: facts, assumptions, unresolved items, permissions, and human review.
10. Checklist/summary: first actions, completion criteria, and reference links.
Template acceptance criteria: Representative layouts render without clipping or unintended overlap; titles and body text remain legible; repeated margins, footer, color, and typography are consistent; diagrams remain editable; each template has exact editable-field documentation; package validation and full-size visual QA pass.
Deadline: Not specified.
